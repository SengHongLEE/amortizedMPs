# 接触时序与训练目标对照

这些实验服务于可靠上阶和其他地形回归，不改变默认任务，也不代表已解决楼梯。

## 接触等待

诊断入口：

```bash
python -B legged_gym/legged_gym/scripts/diagnose_proprio_stairs.py \
  --checkpoint <checkpoint> --output <新目录> --seconds 20 \
  --repeats 8 --speed .5 --contact-wait .08
```

在垂直轨迹相位 1.5π（当前探地最深处），如果尚未形成连续 25 ms 接触，
局部振子等待，最多 80 ms；正常触地后或超时后恢复。参考时钟继续运行。
接触输入沿用现有控制器的足端力阈值，没有增加地形观察。

`contact_phase_gate.py` 只附加到诊断实例。关闭等待与原控制器数值一致，
局部重置和超时释放经过单元检查。附加的等待/支撑状态尚未加入 actor 输入，
因此不能直接把这个诊断实现用于训练；若实验有效，需要建立版本化状态接口。
等待也可能造成支撑脚相对机身停止移动，影响平地稳定性，必须实测。

本次 0.5 m/s、每高度8初态的结果：平地5/8、2 cm 1/8、4/6/8 cm均0/8，
8 cm跌倒7/8。与原控制器相比明显退化，不采用。它仅否定当前局部冻结方法，
不能据此推断所有接触自适应都无效。记录在
`diagnosis_v2_round2_200_contact_wait/summary.json`。

## 高低层任务目标对齐

现有高层选择奖励包含四个各权重为 1 的效率/接触项和权重为 0.4 的跟踪项。
在其他变量相同、命令 0.5 m/s 时，速度从准确跟踪降为零，仅使跟踪项下降
`0.4*tanh(0.5**4) ≈ 0.02497`（乘 dt 之前）。
这证明该项对低速停滞不敏感，但高层目标是否实际阻碍上阶仍需训练对照。

```bash
python -u -B legged_gym/legged_gym/scripts/train_adaptive_equilibrium.py \
  --checkpoint <warmstart> --output <新目录> --iterations 100 \
  --num-envs 2048 --learning-rate .00015 \
  --minimum-level 6 --initial-level 8 --stair-weight 3 --terrain-cols 20 \
  --task-aligned-selection
```

此选项把配置中的 `rewards.primitive_selection_rewards` 设为
`modulation_param_rewards`，并从 `rewards.scales` 复制对应高层权重。
动作空间、控制器、观测和地形不改变。未传该选项时保留源 run 的奖励配置；
已对齐的 run 继续训练时也会保留该配置。

高低层使用相同项时，高层日志使用 `selection_` 前缀，避免重复累计到低层
原始指标。已通过共享奖励值、日志独立性及真实 CUDA 高低层 PPO 更新验证。
两组主实验从同一未更新的 v3 warmstart、同种子和同课程出发：

- 原奖励：`1021_modal_v3_mixed_round1_bounds`
- 对齐奖励：`1021_modal_v3_task_aligned_round1`

对齐奖励不包含原独立的步态切换惩罚；应同时检查步态切换、稳定性和各地形
通过率。不能仅凭新奖励曲线较高认定能力提升。

## 明确的慢速时序初始化

`train_adaptive_equilibrium.py --timing-prior .55 .1 .12` 将六个低层输出头初始化为：
频率倍率0.55、支撑占空比偏移+0.1、四腿摆动高度0.12 m。
这会清零这六行输出权重、设置相应归一化偏置，并使用`--new-action-std`
设置其探索标准差（默认0.2）。前16个空间动作头和其他网络参数保留。

这是有意改变物理策略的初始化，不是无损迁移。继续训练时省略该选项，
避免重新清空已经学到的时序输出。初始化来源及参数写入provenance。
由于历史直接降频回放会损害平地，需要从较易课程重新训练，再逐步提升；
不能把降频后一次回放失败当成重新训练必然失败的证据。

该慢速初始化的未训练回放为flat95/96、stairs46/96，8 cm上阶1/24、
下阶8/24。正式训练从floor0/initial1开始，200更新；这同时改变初始化与
课程起点，不作为单因素因果结论。原奖励v3训练100更新的8 cm上阶仍1/24。

## 水平立面冲击

v2_200的8 cm第一阶附近，水平力>10 N且Fz<=1 N的候选事件占足端子步
约1.88%；约86.1%的相关策略采样中障碍反射峰值仍小于0.05。
这只是力信号分类，不能确定每个事件都来自立面。

`diagnose_proprio_stairs.py --horizontal-obstacle` 在摆动期0.15π–π将该信号
补充到障碍反射，保持竖直支撑/提前触地/缺接触判定不变。
未发生水平冲击时与原动力学数值一致；诊断中还要检查额外抬腿是否真正及时，
不能以“检测信号增加”替代跨越成功。该功能尚不在生产控制器中。

实测平地及2/4/6 cm均8/8，8 cm仍0/8、跌倒8/8（原为4/8），不采用。

## 目标对齐的首轮证据

第50次更新在原配对初态上，8 cm上阶从原奖励版本的2/24提高到12/24，
其他七类地形均96/96。但独立seed321、每速度32初态后，上阶为
4/32、13/32、12/32，共29/96；下阶90/96。尚不能称为可靠爬楼。
成功episode的速度误差也较大，原小样本三个命令下分别约
0.282/0.404/0.683 m/s；后续验收需同时审视速度。

第100次更新的原配对测试回落至8 cm上阶9/24，其他七类仍均96/96。
独立seed321的原始v1对照为上阶2/96、下阶94/96，与对齐50更新初态SHA相同
（`5fbeb1e96fb3ec90f015ff06f5be537caba0b2a716cf3263b269426d58f178b0`）。
因此保留第50次更新作为后续精调起点，仍未达到验收标准。

该独立上阶组按互斥顺序“成功、跌倒、未跌倒但越过侧向走廊、其余未通过”
分类：原v1分别为2/74/18/2，对齐50为29/59/7/1。
当前主要失败仍是跌倒，不是停在台阶前直到超时；不能仅增加前进奖励就假定
剩余问题会消失。这里“跌倒”沿用环境终止判据（机身碰撞或相对地面高度不足）。

`--entropy-coef`及`--modulation-std-scale`允许后续显式调整探索，
不修改推理动作均值；缩放在初始化时只执行一次，继续训练时应省略重复缩放。

精调运行 `1021_modal_v3_task_aligned_refine_round2` 从上述50更新出发：
200更新、2048环境、学习率0.0001、熵系数0.001、连续动作std乘0.5，
课程floor8/initial9、stairs权重3、20列保留其余七类及双向。
warmstart逐张量验证确定性权重完全保留、仅std减半；第10次更新高低策略均已更新且有限。
这是多项训练设置的组合精调，不能解释为某个单因素的因果证据。

## 指定实际台阶高度的评估

默认difficulty=0.5在原[0.01,0.08]范围内对应4.5 cm。
验收6/7/8 cm请使用：

```bash
python legged_gym/legged_gym/scripts/evaluate_proprio_terrain.py \
  --checkpoint PATH_TO_CHECKPOINT --output NEW_REPORT_DIRECTORY \
  --terrains stairs --stair-heights .06 .07 .08 --repeats 32 \
  --seed 321 --terrain-seed 3
```

`--stair-heights`与`--difficulties`互斥，仅用于stairs子集。
高度必须递增、为正且能够在当前vertical_scale下精确生成；无法表示时直接报错，
不会悄悄降低高度。报告保存请求高度及完整有效配置。距离、侧偏、首episode和跌倒
判据与全地形评估一致。几何测试验证两种方向实际高程图的每级高度。

对齐50更新的第一次明确高度评估（seed321、terrain_seed3，各速度32初态）：

| 台阶高度 | 上阶 | 下阶 |
|---|---:|---:|
| 6 cm | 96/96 | 96/96 |
| 7 cm | 96/96 | 96/96 |
| 8 cm | 28/96 | 90/96 |

8 cm上阶在0.5/0.8/1.2 m/s下分别6/32、13/32、9/32，共56次跌倒。
能力在7→8 cm出现明显下降，不能用较低台阶的通过率代替8 cm验收。
报告位于`evaluation_modal_v3_task_aligned_50/heights_seed321/report.json`。
此布局初态SHA为`a345d3af9522e17276b1a75a5d05eda725e14343da5ffde7f7967ea70e8bfc30`，
与之前只测8 cm的192环境布局不同。

原v1相同布局对照已完成，初态SHA相同：
6 cm上下阶均96/96，7 cm上90/96、下96/96，8 cm上5/96、下94/96。
目标对齐改进了上阶，但8 cm下阶略有回落；仍需同时验证双向能力。

补测7.5 cm（`height75_seed321`，同种子设置、192环境，布局与上述576环境不同）：
上阶95/96、下阶93/96。三个上阶命令分别32/32、32/32、31/32；
未发生上阶跌倒，下阶跌倒3次。双向高程图测试已包含7.5 cm，确认并未量化到7 cm。
当前线性10行课程最后两级实际为7→8 cm；7.5 cm近乎通过、8 cm明显退步，
说明应进一步比较边界处的接触过程，不能仅凭此断言加课程级数即可修复。

精调第50更新的全地形结果暂时退步：8 cm上阶7/24，ramp90/96、wave93/96；
flat/slope/rough_slope/rough/rubble仍96/96。继续保留首轮对齐50作为比较基准。
> 后续网格审计发现：以下历史实验中，≤7.5 cm的楼梯立面被全局斜率阈值
> 转成10 cm长的小斜坡，8 cm才是竖直面。低台阶结果不能作为真实楼梯验收。
> 修正和复现接口见[楼梯网格课程说明](stair-mesh-curriculum.md)。
